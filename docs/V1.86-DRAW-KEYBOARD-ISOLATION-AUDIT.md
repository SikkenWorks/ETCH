# ETCH V1.86 — DRAW Keyboard Isolation Audit

## Reported symptom

On a physical M-VAVE FM1 running V1.85, pressing a piano key after modifying a waveform in DRAW can make another unintended waveform edit.

## Confirmed code-level cause / hardware hypothesis

The V1.85 DRAW dispatcher in `firmware/fm1-native/bringup.c` processes encoder deltas (`dm`, `dd`, `up`, `down`) and calls `etch_editor_move_xy128()` and `etch_editor_add_partial()` with no isolation from piano-key changes. `etch_editor_move_xy128()` changes samples whenever a nonzero Y delta is delivered. Thus any unexpected encoder count during a key transition is treated as a genuine write (including an Undo checkpoint). The input HAL scans piano keys and encoder quadrature on the same physical multiplexed matrix. This is a **confirmed vulnerable software path**; physical electrical cross-talk is a plausible explanation of the exact spurious counts, but has **not been measured** on the user's FM1 in this environment.

## Fix

- New `firmware/fm1-native/native_draw_key_guard.h` keeps the last observed 27-key mask and timestamp of physical key transitions.
- In DRAW, a fresh note-on, note-off, or rapid-tap press edge discards encoder input for a 65 ms transition period. Suppressed deltas are never replayed.
- During stable held notes, editing is restored. Piano notes are not gated or muted; the audio ISR and key states are unchanged.
- The guard is reinitialized when entering the DRAW page so old note events cannot contaminate a new editing session.
- Isolation is limited to the waveform editor. All other UI screens and input dispatch are unchanged.
- No changes to audio engine, wavetable serialization, project codec (`PJT32`), OTA code, USB identity (`FM-1_1500`) or protected flash regions.

### Tradeoff

Legitimate encoder motion performed at the exact moment of pressing or releasing a key can also be discarded for up to 65 ms. This is deliberate and avoids false destructive edits. Editing is not disabled for an entire held note.

## Packaging

- `release/ETCH-V1.86.fwsc`: single regular public firmware package.
- `compat/ETCH-V1.86-LEGACY-STOCK-HEAD.fwsc`: installer compatibility path only, **not** stock firmware restoration.
- Both were generated from the normal V1.86 app, preserving their corresponding V1.85 bootheaders and trusted loaders.
- `WebInstaller.html` embeds both new packages with verified SHA-256; its clean PHOSPHOR UI remains unchanged except version references.

## What remains unproven

Software tests cannot prove that every spurious encoder event on a particular FM1 is confined within the 65 ms input window. The result needs a physical test reproducing the original symptom: draw with K2, immediately press several distinct piano keys, and compare waveform points before/after. No on-device flash, long-term USB-audio soak, or physical recovery test was performed. Flashing on a sole device without independently proven recovery remains risky.
