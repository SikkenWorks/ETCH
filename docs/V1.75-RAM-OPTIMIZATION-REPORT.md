# ETCH V1.75 – DSP memory optimization and compatibility audit

**Date:** 29 October 2026  
**Status:** cross-built, host regression tested, packaged; not tested on a physical FM1. No ROM-level restore tested here.

## Confirmed root cause

In V1.74, `struct etch_wave_editor` contained two independent arrays `history[16][3][128]` and `redo[16][3][128]` of signed 16-bit PCM waveform points. Each array reserved **12,288 bytes**, although the total number of reachable undo+redo states is at most 16. More states were statically reserved than the editor can use at the same time.

## Correction

`firmware/fm1-native/wave_editor.h` now contains one `history[16][3][128]` buffer. In `wave_editor.c`, an undo swaps the current 3×128 points with the previous ring slot (that slot becomes the next redo entry); redo performs the inverse swap. Checkpointing invalidates redo after a new edit, and full history overwrites the oldest undo slot as in V1.74. All values remain bit-exact int16, with no lossy encoding. The editor is a transient RAM-only structure and is **not** written to the PJT31 project format.

| `.ram_text` (16 KiB) | 2,888 B | 2,888 B | 13,496 B |
| `.uac_ram` (8 KiB) | 6,604 B | 6,604 B | 1,588 B |
| `.data` + `.bss` (96 KiB) | 94,300 B | 94,300 B | 4,004 B |

**Proven static SRAM saving: 12,288 B.** The unchanged ELF stack guard locations were verified in `release/V1.75-SRAM-AUDIT.json`. These figures do not measure runtime stack high water, heap use or actual CPU cycles on the physical device.

## Tests actually performed

- 25,032 operations with a deterministic, V1.74-equivalent reference model. All 3 waves and every undo/redo count, ring head and edited point were compared after each step: PASS.
- Existing wave editor, XY32, harmonic, spectral, audio, MIDI, sequencer, polyphony, FX, patch swap, projects, storage, LCD scope and USB-audio host cases: **20/20 PASS**.
- Additional integrated V1.75 undo+redo regression: **1/1 PASS**.
- Native `.fwsc` OTA packet replay against the actual V1.75 package: **PASS**. This is host simulated, not a physical transition.
- JieLi pi32v2 builds without UAC, with 44.1-kHz UAC and with 48-kHz UAC: **PASS**.
- Firmware container checksum, preserved `FM-1_1500` identity and SHA-256 parity of embedded firmware: **PASS**.

## Preservation / limitations

Only the editor's undo/redo storage and its algorithms changed in the functional native source. The firmware version display was updated separately; no FX algorithms, wave-editor tools, UI page IDs, MIDI, USB, storage serializers, project formats, recovery or OTA native implementation were removed. All third-party license files retained.

**Still unverified:** FM1 hardware runs, power-loss and independent ROM recovery, real USB 48-kHz stress, full hardware 62-screen pixel QA, original external Felucca/stock transitions and actual CPU gains. The prior 4-byte POOL margin is remedied, but other SRAM areas remain tight and require physical stack/runtime measurement.
