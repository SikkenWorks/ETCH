# ETCH V1.83 – Native UI Alignment & Release Audit

## Scope and confirmed code changes

**Baseline:** ETCH V1.82 complete native source. **Modified native source file:** `firmware/fm1-native/bringup.c` only. 118 C/H/S/LD native files retained; none removed. Added tests and release scripts without deleting or simplifying existing synth, sequencer, presets, effects, USB, project-storage, recovery or OTA functions.

1. **Global footer:** bounded 4-column centered labels and values. The right boundary of K4 remains at/below pixel 240. Long labels are clipped inside their own cells.
2. **MORPH:** original free-placed text/values replaced with two stable column regions (`x=14..118` and `x=122..226`). The original WAVE A/B slot numbers and K3 MORPH, K4 C RATE, ALG ETCH values are retained. Each label+value is horizontally centered as a pair, guaranteeing a gap and no overlap at 0..1000 in the geometry test.
3. **Version + workflow:** `V183 S` or `V183 A` forms one right-aligned 6-character string in the reserved `x=192..240` header zone, on the same baseline. All other versioned headers call the shared helper. Main waveform header invalidation includes workflow-state changes.
4. **Palette:** V1.82 PHOSPHOR RGB565 mapping unchanged.

## 48 kHz RAM sections after V1.83

- `.bss`: 93,900 bytes within its linker allocation.
- `.pool`: 334,260 bytes / 344,064 capacity; 9,804 bytes free.
- `.uac_ram`: 6,604 bytes / 8,192; 1,588 bytes free.
- `.noinit`: 12,148 bytes / 12,288; 140 bytes free.
- The linker/audit also passes the RAM/stack boundary checks. This does **not** prove runtime stack usage or physical device stability.

## Identity, persistence and OTA safety

- **Product/USB identity:** `FM-1_1500` retained.
- **Project storage format:** `PJT31` retained.
- **Protected header:** first 16 KiB of release V1.82 package matches V1.83 byte-for-byte.
- **Trusted OTA loader:** matches V1.82 byte-for-byte.
- **Release policy:** one regular `release/ETCH-V1.83.fwsc`. The `compat/` stock-head package remains a legacy installer compatibility path, not another official release firmware.
- **No physical firmware transition or power-loss recovery** tested; do not interpret software checks as guaranteed cross-firmware safety.

## Screenshot methodology / scope

`release/V1.83-UI-PREVIEWS/` contains four 1920 × 1920 nearest-neighbor previews for SOUND and MORPH (SIMPLE/ADVANCED). They reuse the **unchanged waveform graphics** of the captured V1.82 native renderer and redraw only changed header/footer regions using the extracted **V1.83 native C bitmap-font/layout functions**. They are *not* a complete fresh execution of all 63 native screens. Every rendered color uses the firmware RGB565 PHOSPHOR palette. Dynamic runtime states and physical display clipping still need verification.

## Recommended on-device test before public release

Use a recoverable/test FM1. Check header spacing and all value extremes, rotate K3 MORPH 0..100, K4 rate limits, switch SIMPLE/ADVANCED and check live S/A header updates; inspect all FX/SEQ/MIDI screens and ensure no text overlaps; retest USB audio, project SAVE, OTA and recovery. Flashing the only FM1 without a proven recovery path remains risky.
