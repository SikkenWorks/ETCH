# ETCH V1.79 — Boot Animation & Storage UI Stability Audit

Release date: 29 October 2026. Status: **software-tested experimental firmware; not tested on a physical FM1**.

## Root cause and correction

V1.78's first-boot storage ownership prompt had a visible `lcd_fill()` clearing the LCD panel and reconstructing the entire display on every relevant interaction and periodically while SAVE was held. The SPI LCD could present an empty intermediate frame, perceived as flicker.

V1.79 draws the storage prompt's mutable 240×173 pixel area in ETCH's **existing** RGB565 DMA-safe RAM canvas. Its header uses the existing 240×66 scope blit. The complete composited image is committed before being transferred to the LCD; dirty-state caching discards unchanged renders and displays the SAVE-hold bar in 12 bounded steps. There is no extra permanent framebuffer, no flash operation in the paint path and no change to the pre-existing storage permission state machine. This addresses the known software-side cause; a real FM1 LCD test is still required to verify perceived flicker is gone.

## New cold-boot experience

1. Nine deterministic, colored RGB-registration and scanline/VHS-inspired glitch frames (requested delay 42 ms each, plus LCD transfer time).
2. A clean **SIKKENWORKS** title with **BORN OUT OF PASSION.**, held still for 1,000 ms with watchdog feeding.
3. A stable **ETCH** screen prompts **SIMPLE / ADVANCED**; SIMPLE is selected by default. Turn **K1** (or SELECT rotary) and press the physical **SEL** button to confirm.
4. If foreign/locked project storage was detected, the existing **FORMAT FOR ETCH? YES/NO** prompt appears *after* selecting the workflow. Its default is NO. Formatting still requires an additional SEL confirmation, releasing SAVE and a fresh 3-second SAVE hold.
5. The chosen mode lasts for the current session and does not change `PJT31` projects; all 62 ADVANCED screen IDs remain available. Boot-level ROM recovery (OCT-), REC Safe Mode and SEQ keyboard startup retain priority and bypass the intro question.

No audio DSP work runs during the early glitch animation; it completes before normal audio initialization.

## Preservation and limitations

- Compared with V1.78, **all 114 previous native C, header, assembly and linker files are present**. Only `bringup.c` was modified; two new small UI-control headers were added. Existing storage/OTA/audio source files were not modified.
- The WebInstaller includes the new **single regular** `ETCH-V1.79.fwsc` and retains a separate *legacy* header package internally. The legacy variant is ETCH, **not stock firmware**.
- A successful build and host-level UI dirty-state test do not prove LCD behavior or audiovisual performance on the real device. Real boot timing, USB-audio load, audio output gating and power-loss/flash restoration remain hardware-unverified.
- Do not flash or format on the only FM1 without a proven independent rescue path and a backup of any data that may be erased.
