# ETCH V1.76: ORGANIC DRIFT stabilization and test record

## Confirmed root cause (V1.75 source)

In `firmware/fm1-native/audio_core.c` the old CONTROL tick ran once per 32 PCM frames and applied `os->pitch += (os->goal-os->pitch)/16`. At 44.1 kHz that smoothing had a time constant around 12 ms (about 63% toward the new target). Targets were updated every 4,000–40,000 frames (0.09–0.91 s), so the musical result was repeated brief pitch changes separated by holds. This is different from slow continuous analog oscillator movement. The code also immediately bypassed drift on a live zero setting.

## Exact V1.76 correction

- The oscillator pitch is now interpolated between bounded random pitches by monotonic, zero-end-slope quadratic ease-in/out.
- Rate 0 is about 9 seconds between random goals, RATE 100 about 2.5 seconds (44.1 kHz, ~8% longer at 48k).
- `time` packs duration (upper 16 bits) and control ticks elapsed (lower 16), while existing `pitch` and `goal` serve as the segment endpoints. No additional per-voice allocations or RAM arrays.
- New notes begin neutral and move toward their first drift target. Targets are continuous at segment boundaries; nominal max dynamic pitch depth stays +/-25 cents.
- DRIFT=0 during a running note eases the moving component back toward zero over ~1.5 seconds; static per-note VARIANCE is left untouched. Newly zeroed presets continue to bypass exactly.
- The original fixed source code's mono-only gate is left as-is: the ORGANIC editor applies in MONO, not POLY. No other synthesizer modes or project serialization changed.
- Interpolation is computed once every 32 frames, using bounded 32-bit arithmetic; no new allocations or sample-loop math.

## Tests run in this session

- Native `test_native_organic_smooth_v176.c`, ASan/UBSan: 2,424 random segment sweeps over all 101 RATE values, monotonic motion, endpoints and <=2 Q16 pitch units of change in each 32-sample interval (about 0.05 cents), with continuity and zero-depth checks: **PASS**.
- Existing `organic_v123`, `audio`, `midi`, `fx`, `poly`, `performance`, `overload`, `project`, `patch_swap`, `fx_pcm_v174`, `v175_shared_undo`, `living_v125`, `mono_advanced_v100`, `usb_audio_48k`: **14/14 PASS**.
- JieLi pi32v2 builds: native storage+OTA, USB audio 44.1 and 48 kHz: **all compile**. Application+entry audits pass.
- Static memory (48k build): `.pool` 331,772/344,064, 12,292 free; `.bss` 94,204; UAC 6,604/8,192. **No extra static RAM**, but stack high-water and per-voice CPU time are not physically measured.

## Not tested or guaranteed

Not tested on a physical FM1: perceived sound, timing under load, USB underruns, power interruption, OTA migration, loader handoff, ROM recovery. Do not use the `.fwsc` on a sole or unrecoverable device without an independently proven restore path. The native tests do not guarantee universal cross-firmware OTA compatibility.

- Off-drift PCM regression versus unmodified V1.75 `audio_core.c`: all four `test_v145_audio_parity.c` scene checksums matched exactly (`3d41dc8f`, `774f17eb`, `22ccfae5`, `977419b8`).
