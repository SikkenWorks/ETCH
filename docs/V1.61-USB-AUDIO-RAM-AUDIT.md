# ETCH V1.61 — USB-audio RAM allocation audit

**Scope:** complete FM1 native application based on ETCH V1.60, enabled USB audio, no features removed. **Status: software verification only**. No physical FM1 connection, USB host recording test, flash/power-loss trial or independent recovery test has been performed.

## Reproduced root cause

With original V1.60 `--storage --updater --usb-audio`, the JieLi linker fails: `.bss` overflows the **96 KiB** RAM region by **2,332 bytes**, with `.bss` overlapping the fixed DSP pool. The V1.60 non-UAC release uses approximately 98,204 bytes of `.bss` plus 96 bytes of `.data` in that 98,304-byte region (**4 bytes free**). Its `.pool` is 344,060 of 344,064 bytes (4 bytes free). It cannot safely accommodate a new USB stream ring in ordinary RAM. The originally supplied release was built **without** USB audio even though the source offered a compile-time UAC option.

This is **static memory exhaustion**, not an observed heap allocation failure. Excess USB-audio computation on real hardware is a separate, currently unverified risk.

## Exact changes

1. Preserve byte-identical audited `app.ld` for the non-UAC build. Add a separate `app-uac.ld` used exclusively when `--usb-audio` or `--usb-audio-48k` is set.
2. Split the existing 24 KiB RAMTEXT reservation `0x01C00000..0x01C05FFF` into 16 KiB of executable `.ram_text` at `0x01C00000..0x01C03FFF` and 8 KiB non-persistent scratch `.uac_ram` at `0x01C04000..0x01C05FFF`. Keep the reserved `0x01C06000..0x01C07FFF` debug area, the protected `.noinit` and the bootloader/recovery mailbox untouched. A linker overflow fails the build.
3. Move the **512-frame stereo 16-bit USB ring** (`2,048 B`), **USB IN packet TX buffer** (`196 B at 48 kHz`, `184 B at 44.1 kHz`), **FIR history** (`264 B at 48 kHz`), and **double-buffered oscilloscope captures** (`4,096 B`) into `.uac_ram`. Keep queue lengths, sample depth, screen resolution and effects unchanged.
4. Eliminate the separate 1,024-byte `native_usb_stereo` copy. The USB tap now reads the finalized, post-gain/post-fade `native_dma` samples after the ALNK buffer has been filled, shifting the original Q15-by-7 DAC words back into Q15. Generic Felucca USB tests keep the original unshifted input convention. No flash/audio ISR heap allocation was added.
5. The scope buffers are zeroed by existing `native_start()` before use. Incoming USB audio samples are published only after ring priming. Endpoint packets are fully written before transfer; the `.uac_ram` section is NOLOAD by design. The normal `.bss` remains boot-cleared.
6. Enhance native ELF verifier and add `tools/check_uac_memory.py` to reject overlapping `.ram_text`, `.uac_ram`, `.bss`, `.pool`, `.noinit`, or unsafe flash offsets. Preserve original package identity `FM-1_1500`, USB-MIDI OTA state machine, and PJT31 project format. A single **official ETCH-V1.61.fwsc** ships with ETCH-HEAD; the hidden legacy STOCK-HEAD option is installer-only and is not official stock firmware.

## Target section measurements (JieLi pi32v2 native)

| SRAM allocation | V1.61 44.1 kHz | V1.61 dual-rate 48 kHz | Bound |
|---|---:|---:|---:|
| `.ram_text` | 2,888 B | 2,888 B | 16,384 B |
| `.uac_ram` | 6,328 B | 6,604 B | 8,192 B |
| `.bss` | 94,204 B | 94,204 B | 98,304 B minus 96 B `.data` |
| `.data` | 96 B | 96 B | same 96 KiB window |
| `.pool` | 344,060 B | 344,060 B | 344,064 B |
| `.noinit` | 12,148 B | 12,148 B | safe window 12,288 B |
| `.bss + .data` slack | 4,004 B | 4,004 B | 0 B minimum |
| `.uac_ram` slack | 1,864 B | 1,588 B | 0 B minimum |

The DSP POOL (4 B free) and protected NOINIT (140 B free) remain extremely constrained. This patch **does not** create general-purpose free memory in those sections; new features must not allocate there without another architectural memory audit. The UAC RAM window must not be reused by future RAMTEXT code, OTA handoff routines or debug extensions without revalidating the actual FM1 address map.

## Tests actually run

- **FAIL before fix**: JieLi native build `--storage --updater --usb-audio`, `.bss` overflowed by 2,332 B.
- **PASS after fix**: JieLi native `--storage --updater --usb-audio` and `--storage --updater --usb-audio-48k` with native app packaging and XIP verification. Original `--storage --updater` rebuilt byte-for-byte identically to supplied V1.60 **before the visible V161 version-label change**.
- **PASS**: target section audit for both UAC variants. Current dual-rate ELF app 219,180 B; app XIP slot 581,564 B.
- **PASS**: USB-MIDI identity and UAC descriptors, 60-second 44.1 kHz drift simulation, 44.1 ↔ 48 kHz transitions and 2 × 120-second 48 kHz host-soak simulation, new DAC-Q15<<7 equivalent test, IRQ bridge and audio timing tests. USB host and physical audio peripherals were not emulated.
- **PASS**: new `.fwsc` CRC/identity/pinned boothead/pinned OTA payload checks; WebInstaller embedded bytes equal packaged files and SHA-256; Node.js installer CHECK/WRITE and loader-handshake simulation; unchanged pinned product identity check; synthetic alternate-loader native test and native check of V1.61 ETCH package.
- **Known incomplete test**: old standalone `test_native_dma.c` does not compile because its mock harness lacks `native_analog_gate_test`, `native_mono_mode` and other symbols from the complete bringup source; those references already existed in V1.60. This does **not** indicate a failure of the JieLi target DMA build, but prevents claiming a fully green legacy host suite. The extended native regression run was interrupted by execution timeout and has no complete pass count.
- **NOT TESTED**: real FM1 USB 44.1/48 kHz enumeration, recording integrity, CPU load with 8 voices/FX, unplug/replug stress, direct Felucca-to-ETCH-to-Felucca transition, and hardware recovery. Users must not regard the `.fwsc` as hardware-qualified.

## Rebuild commands

```sh
export JIELI_TOOLCHAIN=/path/to/jieli-linux-toolchains-20250324.1
python firmware/fm1-native/build.py --storage --updater --usb-audio
python firmware/fm1-native/build.py --storage --updater --usb-audio-48k
python tools/check_uac_memory.py build/fm1-native-storage-updater-uac48-p05/etch-native.elf
python tools/run_native_tests.py --only usb,usb_audio,usb_audio_soak,usb_audio_48k,usb_audio_dma_shift,irq_bridge,audio_timing
python tools/build_v161_release.py
python tools/check_pinned_identity.py
node tests/test_v161_firmware.mjs
```

**Flash safety:** do not flash an unverified experimental USB-audio build to the only unit without an independently tested recovery route. The `app-uac.ld` RAM carve-out is structurally validated against known software regions, not proven against every firmware/ROM use of that SRAM on a real device.
