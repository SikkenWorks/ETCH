# ETCH V1.78: First-boot storage ownership and safety audit

## Scope
The UI offers a storage setup **only** for the ETCH target banks when normal boot receives `ETCH_STORE_FOREIGN`. A storage error caused by a bad flash read (`ETCH_STORE_IO`) is not an invitation to erase. Healthy ETCH storage and a blank target region never trigger the format dialog. Valid older ETCH snapshots in the legacy and spare regions are checked by the existing backend and cannot be overwritten through the onboarding route.

## Button workflow
1. At boot: `FOREIGN STORAGE FOUND / FORMAT FOR ETCH?`. **NO is the default.**
2. K1 (or SELECT rotary) chooses NO or YES; physical SEL button confirms the choice. HOME cancels.
3. YES switches to a separate warning screen. After the confirmation, SAVE must first be **released**, then **held continuously for 3 seconds** to start initialization; releasing early resets the timer.
4. During flash I/O display `FORMATTING... / VERIFYING PROJECT`; on a checked commit display `FORMAT VERIFIED` followed by `SEL: CONTINUE`. On error remain in a modal `FORMAT FAILED`, allowing HOME to exit to RAM-only operation. A format failure never reports success.
5. NO performs zero flash operations. ETCH remains usable in RAM, but project SAVE remains blocked by the foreign storage protection, and the dialog will return on the next normal boot.

## Destructive scope
**Only `0xB4000` through `0xDBFFF`** (80 KiB x 2, Felucca sample slots 2/3) can be initialized. They are not universally empty. A YES permanently destroys their previous contents; owners should back up Felucca samples or other firmware data first. Nothing outside this region may be erased by this operation. The tool does **not** repair every sort of `STORAGE FULL` or I/O error, and is not a device-wide factory reset. ETCH uses the existing versioned, CRC-checked `PJT31` A/B journal and readback. The first boot does not format automatically.

## Trust boundaries
- Native `wave_store.c`: existing `etch_store_initialize_project(...)` checks the confirmation token, verifies the new serialized project fits before erase, rejects valid ETCH data in any candidate bank, erases only the ETCH-owned bank pair, and calls verified project-save.
- Native `wave_store_target.c` and Felucca flash HAL: hard bounded erase/program ranges; UI cannot erase OTA, the bootloader, user presets or recovery areas.
- New `native_storage_boot_prompt.h`: state transitions are pure logic, no flash I/O; modal intercepts normal SAVE and all menu navigation.
- Boot recovery and controller modes bypass the prompt; unknown/failed flash reads are not interpreted as approval to erase.
- Installer continues to embed the immutable `FM-1_1500` product identity, protected 16 KiB header and trusted OTA executable.

## Test coverage
- `tests/test_v178_boot_storage_prompt.c`: no prompt with healthy/blank/faulty storage or Safe Mode, default NO, explicit YES+SEL, fresh released SAVE, 3 s hold, early release, HOME cancel, no retries after failure.
- `tests/test_v178_storage_boot_integration.c`: simulated full flash image, no writes before confirmation, post-format CRC reload, untouched firmware/legacy/OTA/presets sectors, valid ETCH project cannot be reformatted, read failures cannot open the dialog.
- `tests/test_native_storage_takeover_v086.c`: existing A/B four-project commit, readback, power-loss simulation and unrelated data preservation.
- JieLi normal/44.1 kHz USB/48 kHz USB crossbuilds and `.fwsc` integrity audit.

## Not verified
**No real FM1 flash experiment, real-world identification of all other firmware storage, power-loss while erasing an occupied foreign region, on-device readback, OTA update and rollback, audio stress or hardware display inspection was performed.** Do not claim that this is a safe recovery mechanism for every hardware/firmware combination. Preserve a verified backup and an independently validated restore path.

## Final measured host-build results

JieLi builds: normal, UAC 44.1 kHz, UAC 48 kHz **all passed**. UAC 48 kHz binary rebuilt twice and compared byte for byte. Real audio host scenarios: **7/7 passed**. Boot dialog and full flash emulator integration: **passed**, including ASan/UBSan. Previous V0.86 storage takeover and interrupted-write safety test **passed**. Pinned identity, OTA container, WebInstaller embedded bytes and SHA-256 **passed**. Static linker guard audit **passed**.

Measured 48 kHz static free space: 4,004 bytes normal RAM, 1,588 bytes dedicated USB RAM, 10,180 bytes DSP pool, 140 bytes NOINIT. These are **linker margins, not actual stack high-water or physical dynamic free RAM**.

Only two existing native files changed: `bringup.c`, `build.py`. Added `native_storage_boot_prompt.h`. All other earlier native source files, including `wave_store.c`, `wave_store_target.c`, `ota.c`, `ota_target.c`, `usb.c`, and DSP/audio modules are byte-identical.
