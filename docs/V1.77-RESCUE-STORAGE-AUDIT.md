# ETCH V1.77 — RAM preset rescue and storage audit

**Software-tested candidate, not hardware-certified.**

## Emergency warning: unsaved sounds on V1.76

The running V1.76 application has an OTA handshake, MIDI note/CC output and flash storage, but **does not implement a read-current-patch command**. No new browser app can read an arbitrary existing V1.76 live patch via USB-MIDI. Flashing V1.77 requires a reset and will destroy unsaved RAM. Do **not** reboot, flash, power off, wipe, or reset an FM1 holding the only copy of an unsaved patch. Manually document every screen and wave shape while the device still runs. The V1.77 manager is a preventative facility for **sounds created or imported after V1.77 is installed**, not a retrospective V1.76 rescue.

## Root cause and scope

`STORAGE LOCKED` is the on-device text for `ETCH_STORE_FOREIGN`. The existing safe storage implementation refuses to overwrite occupied or unrecognized project banks. Under production `ETCH_STORE_OWNED_ENABLED=1`, ETCH's 0xB4000..0xDC000 double-bank storage overlaps Felucca-family sample-owned flash sectors and must not be auto-erased. A blank initial region or recognized committed ETCH bank is required. A corrupted/torn record or occupied foreign bank must be reviewed separately, not silently formatted. `STORAGE FULL` can independently mean a project exceeds the encoder's fixed-size buffer/flash capacity or the 4 project slots are occupied. **V1.77 does not bypass these safety checks.** It adds a host backup path and a storage-status readout to help the user protect work before any supported, deliberate recovery or format operation.

## New USB-MIDI transport

Uses the existing OTA SysEx envelope, `F0` + 7-bit packed `(00 59 command len24 body inverse_sum_checksum)` + `F7`, without changing identity `FM-1_1500` or OTA-loader behavior.

| Command | Direction | Meaning |
|---|---|---|
| `0x11` | host→device | Existing identity handshake (unchanged) |
| `0x60` | host↔device | Capture active RAM sound; return schema, size, CRC32 and last observed storage status |
| `0x61`/`0x62` | host↔device | Read a bounded, 24-byte snapshot slice |
| `0x63` | host↔device | Upload a sequential slice to RAM staging; acknowledge next offset |
| `0x64` | host↔device | Check received length and CRC32, validate all selected ranges, then audition in RAM only |

The snapshot wire record is `ETCH-LIVE-1`, exactly 1,044 bytes for the current pi32v2 C layout. It contains the active patch record, 3 x 128 waveform points, each wave's FX, complete global FX, per-preset DSP modulation, ORGANIC, LIVING, MOD MATRIX, evolution, harmony, mono mode and selected ARP/sequence timing. It is **not a full PJT31 project**: patterns, all presets, user samples, project catalog and other projects are not included. Transfer is main-thread-only and does not perform flash erase/program. A file is JSON `.etchpreset` with schema, product identity, base64 payload, CRC32 and SHA-256. CRC32 is for accidental corruption detection, not authenticity.

Import replaces the **current live sound** in RAM, and requires silence/transport stopped. It does not persist after reboot. The user must separately perform an on-device project or preset SAVE only when storage is functional. The Web MIDI protocol is experimental and has **not been physically tested** for continuous 24-byte handshakes, interrupts or device reconnection.

## UI feedback

During on-device SAVE from the name editor V1.77 draws `SAVING / VERIFYING` and `DO NOT POWER OFF` before the synchronous flash operation. It retains the existing display logic for checked success and precise failure statuses. There is no simulated percent progress; flash operations are synchronous. Original A/B commit + full readback/checksum-before-commit logic remains unchanged. Failure leaves the active editable RAM sound in place.

## Software verification performed

- JieLi pi32v2 builds: standard, UAC 44.1k, UAC 48k: **passed**.
- Static USB 48k memory audit: `.bss` 4,004 B free, `.pool` 10,196 B free, `.uac_ram` 1,588 B free.
- C record structure and bounds validator: 1,044 bytes, valid record allowed and deliberately out-of-range records rejected.
- JS SysEx packing/checksum test: **48 roundtrips**, **48 intentionally damaged messages rejected**, standard CRC32 vector passed; explicit live READ `0x61` → DATA `0x62` response-correlation regression passed.
- Simulated flash project storage ownership: production-mode test passed with protected flash ranges untouched.
- OTA native replay and fault injection: passed, including 121 I/O positions, corruption/incompatible-loader/bootheader checks, without a premature commit.
- Existing smooth ORGANIC test: 2,424 drift segments passed.
- Firmware packaging check: preserved original 16KiB header, original OTA-loader data, `FM-1_1500` identity, embedded installer payload/hash parity.

**Not proven:** on-device USB-MIDI export/import, recovery from existing V1.76 RAM, hardware flash-format safety, verified storage repair on the user's FM1, complete all-feature regression, or physical audio/USB soak tests. No claim of a fully fixed storage bank or universal firmware compatibility should be made from these software tests.

## User recovery sequence

1. If running V1.76 with an irreplaceable unsaved patch, **do not reboot**. Photograph every relevant UI page and three waveforms; record a sound demo. Neither this HTML app nor a new firmware can extract that V1.76 patch retroactively.
2. Once all sounds are backed up or otherwise safely recreated, install V1.77 only via a separately verified recovery/update path. The released `.fwsc` is still a hardware-unqualified candidate.
3. Connect the V1.77 device in the ETCH Project/Preset Manager and `Check ETCH protocol`, then `Read current sound` and immediately download `.etchpreset`.
4. If storage remains `STORAGE LOCKED`, **do not automatically wipe**. Identify the actual flash owner, back up flash where possible and only then consider deliberate supported reinitialization.
5. To recover an `.etchpreset`, open it in the webapp, connect V1.77, then `Send to FM1 (RAM only)` and confirm. Save on the hardware only once storage is writable.
