# ETCH V1.81 — Advanced FX Bypass, UI Safety and Firmware Audit

**Status:** software-tested release candidate; NOT hardware qualified. Last build on 2026-10-30. No physical FM1 was available.

## User-facing controls

In ADVANCED, **hold FX for 700 ms** to open FX BYPASS. A short FX tap retains the original page navigation. The new FX page is ID 62, appended to existing IDs 0–61. No original page ID or original native source file was removed.

The hub lists effects with nonzero/effective settings. K1 scrolls, K4 or SEL toggles ON/BYP, K2 bypasses all listed effects, K3 restores all listed effects, FX closes. The long-press is detected before FX short-tap navigation to avoid a momentary screen jump. The selected FX name and its ON/BYP status have separate bounded drawing areas in the 240x240 UI. Redraw is avoided when no visible state changes.

## What bypass does and does NOT do

- 22 effect IDs: DRIVE, CHORUS, DELAY, REVERB, RING MOD, CHANNEL EQ, COMPRESSOR, TREMOLO, PHASER, FLANGER, DECIMATOR, WAVEFOLDER, TAPE, REVERSE, VIBRATO, ROTARY, AUTO-WAH, A1/A2/B1/B2 inserts, WAVE C FX.
- Bypass bits are **RAM-only**. A restored effect retrieves its original settings immediately. PJT31 project storage and `.etchpreset` data remain unchanged. The user must not interpret bypass as a permanent disabled-effect preset.
- Native effect-processing code has dedicated masking and early exits for expensive chorus/delay/reverb paths; selected wave inserts and filter/EQ branches are gated as applicable. Masking avoids unnecessary heavy FX computations, but light buffer/state bookkeeping remains. Hence CPU savings are expected, but **zero processor cycles cannot be claimed** and no percentages are claimed without profiling the physical JieLi target.
- When all configured effects are bypassed, the native FX host test confirms PCM dry input equals stereo output for 14,000 samples; one-effect bypass does not disable other active effects. No audio processing change is expected when bypass mask is zero.
- No new flash operations, no change to native OTA protocol, trusted loader, protected bootheader or device product ID.

## Color documentation

`docs/ETCH-V1.81-COLOR-REFERENCE.docx` contains the 32 unique **explicit literal RGB565 codes** encountered in the native UI implementation, with exact code-to-`#RRGGBB` translations and frequency counts. Colors computed dynamically at runtime are not guaranteed to be exhaustively listed. It also includes three proposal palettes; those are suggestions only. The present firmware palette is unchanged.

## Known limits / safe-use notice

Physical FM1 verification, measured CPU reductions, every possible dynamic 240x240 screen state, all external original Felucca packages and recovery after failed updates remain outstanding. This source package and firmware are not a guarantee of physical flash safety. Preserve a known-good recovery route and backup before attempting on-device use.
