# ETCH V1.60 · Cross-Firmware OTA Validation

**Date:** 22 October 2026  
**Release:** V1.60  
**Unchanged USB / package identity:** `FM-1_1500`  
**Project persistence format:** `PJT31` (unchanged)  
**Status:** software-verified experimental firmware candidate. **No physical FM1 flashing or restoration test was performed.**

## Confirmed cause and correction

The supplied native V1.50 `ota.c` rejected any incoming APP_ONLY loader body whose length differed from `6,898` bytes, even when the decoded JieLi/Felucca loader was structurally compatible. It also validated only a small portion of the incoming app area and did not CRC-check the complete incoming `flash.bin` before staging. App-only updates already correctly avoided comparing foreign unused 16 KiB bootheaders and executed a trusted embedded writer rather than the other firmware's executable.

V1.60 retains the trusted writer and original identity but validates incoming UFW directory metadata, complete package data CRCs, both loader headers, executable load address, decoded `FELUCCA-LOADER-1` entry marker, compressed loader stream framing and decoded loader CRC, chip key, SFC app directory, app-region bounds and full app-area/app.bin CRCs. Crucially, the staged writer length is **its own embedded 6,898 bytes**, never the incoming third-party loader length. Readback checks include the trusted executable's CRC and pinned SHA-256. The UFW package itself must be obtained from a trusted, checked distribution; CRC16 alone does not establish authenticity.

The known stock V15 restore exception remains pinned to the exact stock image and loader; no blanket FULL_FLASH support has been added. The temporary `ota-FM-1_015` identity remains separate from the normal `FM-1_1500` identity. No change to USB drivers, audio synthesis, sequencer, UI route definitions or storage format was required. Only the displayed V160 version label changes.

## Build / reproducibility

Use the Linux JieLi toolchain installed outside the repository (do not redistribute its binary package). This project does not include toolchain binaries.

```bash
JIELI_TOOLCHAIN=/absolute/path/to/jieli-linux-toolchains-20250324.1 \
  python3 firmware/fm1-native/build.py --storage --updater
python3 tools/build_v160_packages.py
python3 tools/embed_v160_installer.py
python3 tools/check_pinned_identity.py
node tests/test_v160_firmware.mjs
python3 tests/test_v160_cross_loader.py
cc -std=c11 -O2 tests/test_v150_native_ota.c firmware/fm1-native/native_digest.c -o /tmp/etch-native-ota
/tmp/etch-native-ota release/ETCH-FM1-V1.60-ETCH-HEAD.fwsc
```

The `JIELI_TOOLCHAIN` variable must reference the directory containing `pi32v2/bin/clang` and `common/`. A change to source, compiler, SDK or packaging assets will change SHA-256 hashes: rebuild the app, both `.fwsc` files and the WebInstaller together.

## Pre-installation gates still outstanding

Before release for routine hardware use, obtain original Felucca 1.6/1.1.5, verified stock V15 and any other intended destination packages, verify their published SHA-256, then replay them against the actual native CHECK code. Confirm that their application layouts stay compatible with the FM1 memory map and the trusted APP_ONLY writer. Validate on a recoverable FM1 the two-way transition **ETCH V1.60 → other compatible firmware → ETCH V1.60**, confirm installed/loader identities, and perform independent ROM-level restore rehearsals. A desktop simulation or a valid `.fwsc` checksum is not proof of these conditions.

## Release fingerprints

Actual package and app SHA-256 values are recorded in `RELEASE-MANIFEST.json` and the matching WebInstaller source. `tools/check_pinned_identity.py` is intended to fail the build if a future version silently changes the product ID from `FM-1_1500`. The application UI version may advance independently.
