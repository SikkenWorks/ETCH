# ETCH V1.85 — DRAW responsiveness, tonal character and transient audit

## Confirmed causes in V1.84

1. `bringup.c` inspected knob deltas in its 100 ms main input tick. That was the fastest ordinary DRAW feedback path.
2. `etch_editor_move_xy32()` quantised horizontal editing to 32 grips and applied a 17-point, high-strength smoothing brush, tending to round unlike wave shapes into similar contours.
3. `native_compile_edit()` called the full `etch_editor_compile()` for each edit, reconstructing all three 6-level wavetable banks even when only a single wave changed. The editor compiler uses harmonic reconstruction with 64-bit intermediate sums, so this is material extra non-ISR work.
4. V1.84 already had a 256-sample cubic note attack and a 256-sample wavetable handoff, but the bank and stolen-voice tails used linear fades with non-zero endpoint slopes.

## Corrections

- DRAW-only input checking: 100 ms to 25 ms, other page cadence unchanged.
- All **128 original points** now separately selectable with K1. K2 edits amplitude. ALGORITHM chooses **DETAIL** (5 taps), **SOFT** (17 taps), **EDGE** (1 tap). K3/K4 harmonic controls, wave select, Undo/Redo, and save flow remain.
- DRAW compilation limited to at most one attempt per 70 ms during sustained editing. LCD/cursor input can advance independently; a pending edit compiles immediately on exit.
- `etch_editor_compile_wave_source()` compiles one changed waveform, while other tables are copied byte-for-byte from a published immutable bank into an idle bank. Exact 128-point wave and 16-byte per-wave FX source states are checked in a small DSP-pool cache. GROUPS still uses its established full-bank compilation path.
- Wavetable swaps and stolen voice tails use smoothstep crossfades with zero-slope endpoints. Existing 256-sample note-on fade is untouched. No extra voice state or audio buffer.
- No USB, OTA, project codec or flash layout changes; no new persistent format.

## Performance and memory

A short **desktop-host** benchmark of eight full wavetable compilations against eight one-wave compilations plus copying the two unchanged tables measured roughly 3x throughput improvement. **This is not FM1 CPU profiling**. A 70 ms cap improves the worst-case redraw cadence under repeat movements but does not guarantee 25 ms audible-table latency.

For the 48 kHz JieLi build, linker sections are:

- `.pool`: **335,084 / 344,064 B**, leaving **8,980 B**.
- `.uac_ram`: **6,604 / 8,192 B**, leaving **1,588 B**.
- `.bss`: **93,900 B**, 4,404 B below its 98,304 B allocation maximum (actual memory region limits enforced by linker).
- `.noinit`: **12,148 / 12,288 B**, leaving 140 B.
- New editor compilation source cache occupies **820 B** of `.pool`. No fourth wavetable bank has been allocated.

## Compatibility

- **`FM-1_1500` retained**. Official primary release: `release/ETCH-V1.85.fwsc`.
- Existing 16 KiB protected boot header and trusted incoming OTA loader match the V1.84 primary release byte-for-byte.
- Project format **PJT32**, USB-MIDI SysEx protocol, 1,044-byte `.etchpreset` V2 snapshot and WebInstaller architecture unchanged.
- No flash wipe, format, storage-ownership or loader-validation logic was changed.
- The 64 existing page routes and PHOSPHOR UI remain; DRAW adds only an editor brush selector.

## Limitations

It would be inaccurate to claim all plops eliminated: the new fades specifically reduce digitally generated abrupt transitions. The initial analogue output-enable transient, noisy external amplifiers, and physical performance under heavy USB/polyphonic loads are not verified. Keep an independent restore procedure and a backup before flashing. A firmware update destroys an unsaved RAM-only patch.
