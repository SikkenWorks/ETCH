# ETCH V1.73 — Display Rendering and Stability Audit

**29 October 2026 — SOFTWARE TESTED ONLY. Not a hardware-qualified FM1 firmware.**

## User-visible changes

- Existing SOUND/SIMPLE/ADVANCED workflows, 62 editor IDs, STRING ENS sound, MIDI/FX and PJT31 persistence remain unchanged.
- The 5×7 LCD text glyph renderer now writes direct to the **existing** RGB565 canvas for fully contained scale-1 characters. Non-contained glyphs, boot splash and large characters still use the previous renderer. This removes redundant fill-function calls but does not establish a physical speed-up without profiling.
- All screen compositor entry/commit paths now check the fixed canvas capacity before clearing/writing/sending LCD DMA. Invalid frame dimensions fail closed instead of risking out-of-bounds writes.
- A dedicated test compares every pixel for **8,192 seeded random glyphs** against the old fill algorithm and checks guard canaries, color byte order and invalid border requests.

## Source preservation

- Native source and header files from V1.72: none deleted; only `firmware/fm1-native/bringup.c` changed; two small header files added.
- `audio_core.c`, `native_fx.c`, `usb.c`, `ota.c`, `ota_target.c`, and `native_project_codec.c` are byte-for-byte **identical to V1.72**.
- Native package/USB identity: **FM-1_1500**. Firmware screen version: **V173**. Project format: **PJT31**.
- Original ETCH 16 KiB bootheader and pinned trusted OTA writer preserved by package assembler.

| `.uac_ram` | 6,604 | 6,604 | 1,588 bytes |
| `.pool` | 344,060 | 344,060 | **4 bytes** |

These are **static linker allocations**, not a runtime heap usage measurement. The almost-full pool does not itself prove dynamic memory corruption, but leaves no capacity for additional pooled buffers. No buffers were removed or moved in this release.
