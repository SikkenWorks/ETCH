## Prior functionality

# ETCH

**DRAW. MORPH. MODULATE.**

ETCH is my custom firmware for the M-VAVE FM1, built under SikkenWorks.

I wanted to turn the FM1 into something a little different. Rather than starting with a standard FM algorithm or the usual fixed oscillator shapes, I wanted to actually *draw* the sound. Take a waveform, change it with the hardware controls, save it, blend it with another one, and use a third waveform to modulate the result.

That's basically where ETCH started. It has grown quite a bit since then, but the idea is still the same: make the waveform itself the instrument.

## How it works

Start by drawing or editing a single-cycle waveform directly on the FM1. Save it in the waveform library. You can use those saved waves in different patches, so you don't have to start from scratch every time.

Wave A and Wave B are read at the same oscillator phase. **MORPH** interpolates between their shapes to create a single carrier. Then **Wave C**, another waveform you've drawn or saved, can modulate that carrier. There's an envelope, a filter, drive, per-wave processing and global effects to shape the rest of the sound.

There is a lot more in there too: eight-voice polyphony, a sequencer, an arpeggiator, scale-aware harmony tools, Motion Recording, Wave Genetics and Wave Evolution. **ARP mode 7 (RIFF)** generates little melodic ideas within the selected key and scale; turn K4 to make another one.

When you're editing Wave A, Wave B or Wave C, ETCH lets you hear that individual waveform instead of the complete morphed patch. Wave A FX and Wave B FX also have their own audition path. Leave the editor and you're back to the complete synth.

### A few controls

- **HOME:** short press returns to PLAY. Hold it for **1.5 seconds** to open the named PRESETS browser.
- **PRESETS encoder:** scrolls through saved, named presets **only in the PRESETS browser**. Outside that menu, it adjusts the BPM (30–240) and briefly shows a BPM overlay. K1 selects save slots in the SAVE editors.
- **EDIT / DRAW:** K1 selects the horizontal position, K2 changes the waveform shape, K3 selects a harmonic and K4 adjusts its strength.
- **LFO:** cycle Wave C modulation, Wave C FX, EVOLUTION, ORGANIC, SPECTRAL, LIVING, MOD MATRIX and PATCH BLEND.
- **ARP:** choose an arpeggiator mode, including RIFF; the ARP page cycle now includes RIFF LAB for motif variations.
- **HOME (short) from PRESETS:** exit back to PLAY.

The screen is designed around the waveforms, not just rows of numbers. I wanted it to feel like a tiny oscilloscope that you can actually play.

## V1.31: SPECTRAL control isolation, LIVING audio and safer PATCH BLEND

I went back through the **actual FM1 control path**, after hardware feedback showed that some values could still appear to change each other and LIVING could be practically inaudible.

- **SPECTRAL K3 / K4:** The old `PART LVL` and `BRIGHT` labels were *measurements of the same edited waveform*, not independent parameter setpoints. Both could change whenever either edit changed the waveform. V1.31 now shows **GAIN EDIT** (K3) and **TILT EDIT** (K4), each an independently bounded 0–100 edit position, centred on **50**. - **Preset storage:** The new **PJT27** format stores both SPECTRAL edit positions for every named preset alongside the existing V1.30 advanced state. PJT26 and older projects can still be read. ## V1.28: PATCH BLEND and RIFF 2.0

This iteration adds two ways of taking an idea further without having to start again.

### PATCH BLEND

**PATCH BLEND** is after MOD MATRIX in the **LFO** page cycle. It interpolates between **two complete saved preset snapshots**, using the existing editor and audio-table crossfade machinery. You need at least one stored, valid preset before the editor can operate; two different saved presets make the effect most useful.

| Control | Function |
|---|---|
| **K1 — PATCH A** | Choose the source saved preset, skipping unoccupied slots |
| **K2 — PATCH B** | Choose the target saved preset, skipping unoccupied slots |
| **K3 — BLEND** | Move from 0% (A) to 100% (B) |
| **K4 — ACTIVE** | Turn blending on by rotating clockwise, off by rotating counterclockwise |

The editor blends the **three stored waveform snapshots (A, B and C)**, MORPH, modulation depth, envelope attack/decay/sustain/release, filter cutoff/resonance, drive and chorus/delay/reverb amounts. Discrete per-wave FX configuration and global FX settings switch at the halfway point instead of pretending that incompatible effect modes can be continuously interpolated. The existing wavetable compilation and smooth transitions continue to run outside or alongside the real-time audio path as before.

This feature **does not overwrite the original source/target preset snapshots**. If you like a resulting sound, save it into a preset in the normal way. The *two selected endpoints and current blend knob position are session controls*, not persistent morph automation. This first version does not crossfade two full simultaneously sounding synthesizers, nor does it morph sequencer contents, key/scale or every possible modulation state.

### RIFF 2.0 / RIFF LAB

While working with **ARP mode 7 (RIFF)**, cycle the **ARP** button through **ARP → ARP EDIT → CLOCK → RIFF LAB**. The four controls are:

| Control | Function |
|---|---|
| **K1 — DENSITY** | Set how many notes versus rests the riff contains, 0–100; **50** preserves the old pattern behavior |
| **K2 — MUTATE** | Adjust how strongly the existing motif is changed, 0–100; **0** leaves the original notes alone |
| **K3 — VARIANT** | Regenerate a variation of the current motif without changing the base seed |
| **K4 — NEW RIFF** | Generate a new base motif, as before |

The mutation algorithm keeps the first step of a motif as an anchor and makes controlled changes to later notes/rests. **RIFF is still driven by the shared project BPM and ARP RATE**, including external MIDI-clock following where configured. The new controls are stored per saved patch slot in **PJT25**, and loading PJT24 or older data initializes DENSITY=50, MUTATE=0 and VARIANT=0 so previous riffs retain their original behavior.

## V1.27: Startup audio pop hardening

One thing I really wanted to investigate was a loud startup pop, particularly after the FM1 had been connected to a PC or USB power. The V1.26 audio path already sent **digital silence** before the analog output was enabled and faded in PCM afterwards. But I found a real problem in the startup timing: PC6, the firmware-controlled analog output enable, could still be switched on immediately after a late USB state change due to a three-second bypass.

V1.27 removes that bypass. USB configuration and suspend state must now be stable for **two uninterrupted seconds** before PC6 is enabled. Digital zeros continue through an additional **one-second analog settling interval**, and ETCH still waits for the first finished PLAY screen before its existing sample-by-sample 8192-sample PCM fade. The sound engine, project storage **PJT24**, MOD MATRIX, RIFF timing, waves and effects have not been changed.

**This is a code-tested startup timing fix, not a proven permanent cure for the audible pop.** The GPIO analog-enable transition itself might produce a DC/bias transient, or the pop might happen before ETCH starts, during power-up. Those are hardware questions that require capturing the audio output, PC6 and analog bias on a real FM1. See [`V127-STARTUP-POP-ANALYSIS.md`](V127-STARTUP-POP-ANALYSIS.md) for the code evidence, safe testing protocol and criteria for calling it physically solved.

That V1.27 safety-only release intentionally deferred PATCH BLEND and RIFF 2.0. Both were subsequently added in V1.28, without changing the original V1.27 startup timing safeguard.

## MOD MATRIX (V1.26)

The drawn waveform is still the heart of ETCH. With **MOD MATRIX**, I wanted to give the sound a few more ways to respond to your playing. You can now assign **four independent modulation routes** without having to permanently edit the waveform.

Press **LFO** repeatedly to reach **MOD MATRIX**, directly after LIVING. Use the four FM1 encoders:

- **K1 ROUTE:** choose one of four routes (1–4).
- **K2 SOURCE:** OFF (0), VELOCITY (1), ENVELOPE (2), WAVE C (3) or LIVING (4).
- **K3 DESTINATION:** MORPH (1), C DEPTH (2), FILTER (3) or SPACE (4).
- **K4 AMOUNT:** 0–100. Zero fully disables that route.

The screen displays readable SOURCE and DESTINATION names. MORPH, C DEPTH and FILTER work independently for each sounding voice, so notes played at different velocities or envelope positions need not sound identical. **SPACE is a global stereo effect**; its modulation reads the first active voice rather than creating one reverb per note. Wave C contributes a bipolar modulation signal; velocity, envelope and LIVING contribute unipolar signals. Contributions are bounded and the destinations are clamped to a safe parameter range. This first MOD MATRIX iteration deliberately focuses on four useful destinations rather than pretending every single synth parameter is already routable.

The matrix is **project-scoped**, stored in **PJT24**, and defaults to OFF when loading PJT23 or older projects. With no active routes, the original audio rendering path remains unchanged. RIFF still follows the shared BPM and K2 rate division, and the V1.20–V1.25 sound-design features remain present.

## LIVING WAVES (V1.25)

I wanted the waves in ETCH to feel a little less static after you let go of the controls. **LIVING** is a non-destructive, per-voice layer that slowly changes the harmonic balance of the sound as each note plays. Different notes in a chord develop independently, and their original Wave A/B data remain untouched.

Press **LFO** repeatedly until you reach **LIVING** (after SPECTRAL):

- **K1 DEPTH:** 0–100. How far the harmonic movement goes. At 0, audio is **bit-exactly the same as V1.24** in a dedicated cross-version host PCM comparison.
- **K2 RATE:** 0–100. How quickly the movement completes its cycle, from slow atmosphere to faster motion.
- **K3 COLOR:** 0–100. At 0 the sound darkens by reducing upper harmonics; at 100 upper harmonics are emphasized slightly. Intermediate positions progressively blend between the two.
- **K4 VARY:** 0–100. Introduces a note-dependent time offset, so simultaneous voices do not move in lockstep.

Each voice crossfades between the original band-limited wavetable and a lower-harmonic mip level. Control signals are evaluated at a low rate and interpolated; there is no extra per-sample FFT or changing of stored waveforms. Some relatively simple, sine-like sounds have little high-frequency material to alter, so the effect is clearest on rich drawn or spectrally sculpted waves. The separate ORGANIC and EVOLUTION engines still work.

The four LIVING settings are **project-scoped** and saved with the new backward-readable **PJT23** format. PJT22 and PJT21 projects still load, with LIVING switched off by default. The project engine remains eight-voice where the CPU budget permits; real hardware sound, latency and sustained CPU load are not yet verified.

## SPECTRAL ETCH (V1.24)

After drawing a waveform, I wanted another way to work with the sound itself: **individual harmonics**. Press **LFO** repeatedly to reach **SPECTRAL** after ORGANIC. This is an actual waveform editor, not a cosmetic spectrum display.

- **K1 WAVE:** select Wave A, Wave B, or Wave C.
- **K2 PART:** select partial/harmonic 1–32.
- **K3 GAIN:** turn up/down to increase or decrease that partial by approximately 8% per detent. If the partial is missing, increasing it seeds a small sine partial.
- **K4 BRIGHT:** tilt the harmonic balance. Clockwise adds upper-harmonic energy, counterclockwise reduces it; the spectrum display reports the measured brightness rather than storing a fake knob offset.

The engine analyses the edited cycle and changes its **128-point source waveform**, using the same 512-point sine basis as the normal wavetable compiler. The edited waveform then passes through ETCH's existing six anti-aliased mipmap levels. The heavy harmonic work runs **outside** the real-time audio interrupt. The ordinary 16-step waveform Undo/Redo and Save system continue to work.

Wave A/B spectral changes also change the sound of the existing A/B MORPH. This version does **not** add a separate complex-spectrum morph algorithm; it morphs the two newly sculpted waves using the existing oscillator architecture.

### RIFF tempo (verified in V1.24)

**RIFF Mode 7 already follows ETCH's shared project BPM**; no independent RIFF clock is used. **K2 RATE** changes the beat division and **K4 NEW RIFF** changes only the generated note pattern. To edit the BPM while K4 is generating riffs, open the shared **CLOCK** page from the ARP cycle. With external MIDI clock enabled, the shared performance engine uses the received clock BPM. V1.24 adds explicit 60/120/180 BPM, beat-division, live-tempo and clock-follow regression tests.

## Audio Engine 2.0 (V1.21)

I wanted the synth to feel smoother and more controlled, not just accumulate effects. V1.21 starts that work with narrow crossfades at the transitions between harmonic-limited oscillator tables. The waveform should no longer abruptly switch timbre at a table boundary when notes or pitch bend change. The cutoff and resonance values are also smoothed at audio rate, including sequencer and motion automation.

The eight-voice headroom management from V1.20 is retained. These changes have passed offline host audio tests, but real FM1 CPU headroom and audible quality still require hands-on measurements. This is the first audio-quality pass, not a claim of studio-grade mastering, zero aliasing, or complete click elimination.

## ORGANIC ENGINE (V1.23)

This is a small, independent per-voice variation layer placed before the existing filter and effects. Press **LFO** repeatedly to cycle **MOD → WAVE C FX → EVOLUTION → ORGANIC → SPECTRAL**. In the ORGANIC screen, four physical knobs control:

- **K1 DRIFT (0–100):** maximum slow pitch wandering (up to about ±12 cents).
- **K2 RATE (0–100):** how frequently each note chooses a new drift destination.
- **K3 PHASE (0–100):** randomized starting position of each note's carrier/modulator cycle, applied on note-on.
- **K4 VARY (0–100):** a small stable pitch difference between voices (up to about ±5 cents).

DRIFT and VARY are smoothed and computed at a low-rate DSP control interval. ORGANIC at all zero is a true bypass; older projects decode with everything at zero. **These settings are project-scoped, not individual-preset parameters, in V1.23.** Project storage advances additively to **PJT22**, with the existing PJT21 riff and waveform contents retained.

The Organic effect is not a substitute for a stereo unison oscillator. It does not currently introduce new stereo panning or more than eight oscillator voices. Physical CPU/audio verification is still pending.


## SPACE 2.0 (V1.22)

The waveform itself is still the instrument, but how it sits in a room matters too. V1.22 was the first **SPACE 2.0** DSP pass. I have improved the existing global effects without replacing the original presets, increasing the number of voices or changing the PJT21 save format.

- A small, true fixed-point all-pass diffuser precedes the existing reverberation tank. It adds a little extra scattering to short reflections without adding a second big buffer.
- The reverb feedback is low-pass damped, especially at longer decay settings, to make bright feedback less metallic.
- The stereo chorus now uses fractional, interpolated delay reads with opposite left/right modulation instead of abruptly stepping between sample taps.
- Global FX stay bounded, allocation-free and processed only once per audio sample. Exact dry bypass, serial/parallel routing, previous FX controls and existing reverb-mix endpoints are retained.

This is an **initial quality pass**, not a new convolution or full multi-second hall reverb. There is no FREEZE control in V1.25. The FM1's DSP budget is still limited, and its hardware performance and sound remain **unverified** until measured on a physical unit.

## Distribution and .fwsc status

The V1.31 source and a self-contained experimental browser installer are included. **There is no standalone public `.fwsc` release yet.** The JieLi FM1 container can be generated and statically validated, but neither a safe ROM-level recovery route nor successful installation on a physical FM1 has been demonstrated in this project. `tools/fm1_fwsc.py release-pack` deliberately requires independent recovery proof and a matching app audit. Please do not rename a development `.fwsc.lab` file to claim hardware readiness.


## Release readiness

An earlier V1.23 release contained a firmware identity mismatch: its application source still identified itself as `FM-1_1022` but the installer expected `FM-1_1023` after reboot. **Do not treat that installer as hardware validated or infer successful installation from its checks.** The current V1.31 firmware uses `FM-1_1031` and its browser installer checks the same identity in automated tests.

## Installing and building

The `ETCH-WebInstaller-V1.31.html` file contains an experimental firmware package and a USB-MIDI updater. Open it in desktop Chrome or Edge over HTTPS or localhost, with Web MIDI/SysEx permission enabled. It checks the package, expected firmware identity and protected header, and uses the FM1's existing update protocol. It also provides a stock V15 restore option, but you have to supply the official firmware file yourself.

**Important:** V1.31 is an experimental build, not a physically qualified release. A successful software build or host test does **not** prove that flashing is safe. The FM1 has a single application bank. Without a tested, independent ROM-level backup and restore route, a bad update may leave the instrument unusable. Keep backups and don't flash blindly, especially if you only have one FM1.

Building the device binary requires the JieLi pi32v2 toolchain. The toolchain archive I used is named `jieli-linux-toolchains-20250805.1.tar.xz`, but the folder inside it is named `jieli-linux-toolchains-20250324.1`. Point `JIELI_TOOLCHAIN` to that **extracted folder**, which contains `pi32v2/` and `common/`.

```bash
export JIELI_TOOLCHAIN=/path/to/jieli-linux-toolchains-20250324.1
python3 firmware/fm1-native/build.py --storage --updater
```

The `--storage --updater` options enable experimental flash-storage and firmware-update functionality. They are not a substitute for hardware recovery testing.

A standalone `.fwsc` firmware package is **not** distributed with V1.28. The internal release process can statically check an experimental package using a previously verified V1.27 reference, but neither those checks nor the webinstaller prove that flashing a physical FM1 is safe. The production packaging tool deliberately requires independent recovery evidence. The build script also enables the existing multi-project option when storage is selected.

To run the main host checks:

```bash
python3 tools/audit_felucca_core.py
python3 tests/test_v120_preset_policy.py
python3 tests/test_installer_binary_parity_v128.py
python3 tools/run_native_tests.py --only riff_v128,riff_codec_v128,ui_navigation,riff_bpm_v124,project,store,wave_compression,startup_pop,matrix_v126,organic_v123,spectral_v124,living_v125 --jobs 4
python3 tools/run_native_tests.py --only matrix_v126,living_v125,spectral_v124,riff_bpm_v124,organic_v123,fx_space_v122,fx,fx_stereo,fx_advanced,fx_rc_guard
gcc -std=c11 -O2 tests/test_native_audio_v121.c firmware/fm1-native/audio_core.c firmware/fm1-native/native_performance.c firmware/fm1-native/native_fx.c -o /tmp/etch_audio && /tmp/etch_audio
gcc -std=c11 -O2 tests/test_native_preset_browser.c -o /tmp/etch_presets && /tmp/etch_presets
python3 tools/run_native_tests.py
npm test
cmake -S . -B build/host
cmake --build build/host
ctest --test-dir build/host --output-on-failure
```

The source code is here so you can inspect it, build it and change it. The official M-VAVE V15 firmware is not included.
